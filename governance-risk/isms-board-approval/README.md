# What a Board Must Approve Before Signing Off an ISMS

[Read in English](README.en.md) · [Leer en español](README.es.md)

> **Purpose | Propósito:** show boards and executives what an information security management system actually asks them to decide, using a fictional e-commerce case built on ISO/IEC 27001:2022.
>
> **Portfolio area | Área del portafolio:** [Governance & Risk](../README.md) · [Catalog](../../CATALOG.md)
>
> **Boundary | Límite:** fictional company, public standards, no confidential or third-party material.

**Author | Autor:** Eduardo J. Vega Arguedas (Ed) · [LinkedIn](https://www.linkedin.com/in/eduardovegaa/) · [GitHub](https://github.com/edovega/) · [Program](https://ucenfotec.ac.cr/Carreras/maestria-profesional-en-ciberseguridad-y-seguridad-de-la-informacion/)

This is an executive-oriented article, not an academic submission. It uses a fictional case to show which decisions in an ISMS belong to leadership, not to the security team alone.

Este es un artículo de orientación ejecutiva, no una entrega académica. Usa un caso ficticio para mostrar cuáles decisiones de un SGSI le corresponden a la dirección, y no solo al equipo de seguridad.
